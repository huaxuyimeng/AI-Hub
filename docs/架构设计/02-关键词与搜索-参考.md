## 二、两套独立的意图搜索

文档旧版（`07-关键词与搜索系统-重设计.md` §4.5）描述了一个"统一版"意图搜索，但代码里实际上是**两套完全独立的系统**：

| 系统 | 文件 | 作用域 | 触发 UI | 状态 |
|------|------|--------|---------|------|
| **Model 意图搜索** | `src/lib/news/intent-search.ts` | Model 表（rankings）| rankings 页智能搜索框 | ✅ 后端完成 |
| **News 意图搜索** | `src/lib/news/news-intent.ts` | NewsItem 表（news）| ⚠️ **前端未接入** | ⚠️ 后端就绪 |
| **同义词展开搜索** | `src/lib/news/search.ts` | NewsItem | news 页基础搜索框 | ✅ 完成 |

**为什么两套独立？**
- 两边数据结构差异大：Model 有 `intelligence / speed / priceInput / priceOutput` 等数值字段；NewsItem 有 `category / source / companyTags / dateRange` 等文本字段
- 两边 LLM prompt 模板差异大：Model prompt 强调数值过滤；News prompt 强调时间窗口 + 分类
- 解耦后便于独立迭代

## 三、Provider → Origin 映射（Model 意图搜索）

用户说"中文模型" / "国产" → 系统自动过滤 DeepSeek / Alibaba / Moonshot / MiniMax 等：

```ts
// src/lib/news/intent-search.ts
const PROVIDER_ORIGIN: Record<string, string> = {
  openai: '美国', anthropic: '美国', google: '美国',
  deepseek: '中国', alibaba: '中国', moonshot: '中国', minimax: '中国',
  meta: '美国', xai: '美国', mistral: '法国', ollama: '美国',
  'tencent cloud': '中国', 'baidu cloud': '中国', '字节跳动': '中国',
  'tongyi': '中国', '通义千问': '中国', 'qwen': '中国',
}

function providerMatchesOrigins(providers: string[], origins: string[]): boolean {
  for (const prov of providers) {
    const norm = normalizeProvider(prov)
    const origin = PROVIDER_ORIGIN[norm] ?? PROVIDER_ORIGIN[norm.split(' ')[0]] ?? ''
    if (origins.includes(origin)) return true
  }
  return false
}
```

**LLM prompt 约束**（防止幻觉）：
- provider 必须是枚举内的值之一
- origin 只能是 `["中国"]` 或 `["美国"]`
- 数值类过滤（priceRange / minIntelligence）只在用户明确说时才填

## 四、News 意图搜索的白名单校验

LLM 可能幻觉返回无效分类/厂家，必须白名单校验后丢弃：

```ts
// src/lib/news/news-intent.ts
const VALID_CATEGORIES = new Set([...Object.keys(CATEGORY_KEYWORDS), '未分类'])
const VALID_COMPANIES = new Set(AI_COMPANIES.map(c => c.display))

// LLM 返回后校验：
const category = parseResult.filters?.category
if (category && !VALID_CATEGORIES.has(category)) {
  // LLM 幻觉了，忽略这个过滤条件，不阻断搜索
  delete parseResult.filters.category
}
```

## 五、降级链（两套系统通用）

```
意图搜索调用
  ↓ LLM 解析（gpt-4o-mini）
  ↓ 解析失败 / 超时（AbortController 3.5s）
  ↓ 降级为字面 contains 搜索
  ↓ 同义词展开（TermDictionary.verified=true）
  ↓ 结果返回（标记 degraded=true，让 UI 显示提示）
```

**超时机制**：`Promise.race` 实现 3.5s 超时（chat() 不直接支持 AbortSignal）。

**降级提示**：UI 可根据 `degraded: true` 显示 "LLM 解析超时，已降级为字面搜索"。

## 六、TermDictionary（AI 关键词系统）

### 6.1 Prisma Schema

```prisma
model TermDictionary {
  id           String   @id @default(uuid())
  /// 标准化名称（kebab-case）
  canonical    String   @unique
  /// 显示名称
  displayName  String
  /// 类型：model | concept | company | person
  type         String
  /// 同义词列表（JSON: ["gpt-4", "gpt4", "chatgpt-4"]）
  aliases      Json     @default("[]")
  /// 权重（0-100），用户反馈调整
  weight       Int      @default(50)
  /// 来源：auto | manual | user
  source       String   @default("auto")
  /// 是否已审核
  verified     Boolean  @default(false)
  firstSeen    DateTime @default(now())
  lastVerified DateTime @default(now())
  notes        String?

  @@index([type, verified])
  @@index([weight])
}

model TermEvaluation {
  id           String   @id @default(uuid())
  canonical    String
  /// 评估批次（YYYY-WW）
  batch        String
  /// true_positive | false_positive | uncertain
  label        String
  frequency    Int
  evaluatedAt  DateTime @default(now())

  @@index([batch])
  @@index([canonical])
}
```

### 6.2 4 个脚本 + 1 个 cron

| 文件 | 用途 | 触发 |
|------|------|------|
| `scripts/extract-terms.ts` | 从近 100 条新闻抽取新术语 | 手动 |
| `scripts/expand-synonyms.ts` | 用 LLM 扩展同义词 | 手动 |
| `scripts/review-terms.ts` | 交互式人工审核 | 手动 |
| `scripts/evaluate-terms.ts` | 评估术语质量（每周）| 手动 |
| `src/app/api/cron/refresh-terms/route.ts`（309 行）| 自动化流水线 | cron |

### 6.3 ⚠️ 审核卡点

> **当前 `TermDictionary.verified = true` 计数为 0**——所有 AI 自动抽取的术语都必须经过人工审核才能进生产词表。
> **这是设计如此的安全锁**，不可绕过。
>
> 操作步骤：运行 `npx tsx scripts/review-terms.ts` 逐条 `a/d/e/s`。

### 6.4 5 分钟缓存

`src/lib/news/search.ts` 内置 5 分钟内存缓存（`termsCache`），避免每次搜索拉一次全表。

## 七、关键实现细节

### 7.1 LLM Prompt（Model 意图搜索）

```
你是 AI 模型搜索意图解析器。给定用户查询，提取以下结构化信息：

- query: 核心关键词（去除修饰词，只保留实质名词）
- filters:
  - provider: 厂商列表（OpenAI, Anthropic, Google, DeepSeek, xAI, Meta, Mistral, Alibaba, Moonshot, MiniMax, 字节跳动, 百度, 通义千问, Qwen, Ollama）
  - priceRange: [最小, 最大] USD/M tokens
  - priceField: input | output
  - minIntelligence: 0-100
  - minSpeed: 数值
  - family: 模型家族（claude, gpt, gemini）
  - origin: ["中国"] 或 ["美国"]
- sort: relevance | recent | price-asc | price-desc | intelligence-desc | speed-desc | value-asc | value-desc
  - "便宜" → price-asc
  - "能力强" → intelligence-desc
  - "性价比" → value-asc / value-desc
  - "最新" → recent
  - 默认 → value-asc
- expandSynonyms: true

只返回 JSON，不要解释。
```

### 7.2 Prisma 查询构建（避免字段覆盖）

```ts
// src/lib/news/intent-search.ts: H-5 修复
// 错误做法：多次赋值同一字段导致后者覆盖前者
const providerConditions: object[] = []
if (filters.provider?.length) {
  providerConditions.push(...normalized.map(p => ({ provider: { contains: p } })))
}
// 最后统一合并为 AND 组
if (providerConditions.length) {
  where.AND = providerConditions
}
```

### 7.3 排序映射

| UI 输入 | Prisma orderBy |
|---|---|
| `recent` | `{ updatedAt: 'desc' }` |
| `price-asc` | `{ priceInput: 'asc' }` |
| `price-desc` | `{ priceInput: 'desc' }` |
| `intelligence-desc` | `{ intelligence: 'desc' }` |
| `speed-desc` | `{ speed: 'desc' }` |
| `value-asc` / `value-desc` | `calculateValueScore()` 后内存排序 |
