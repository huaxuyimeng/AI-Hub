# Fix Bug Skill

## 1. 调用流程（严格六步，禁止跳步）

### Step 1：复现确认

- 输出"我能复现的最小步骤"
- 让用户确认能复现 → 进入 Step 2

### Step 2：完整阅读相关代码

- 列出涉及的所有文件 + 行号区间
- 画出调用链（input → … → output）

### Step 3：多假设根因分析（≥ 2 个候选）

每个候选必须包含：

- **现象**：观察到的具体异常行为
- **证据**：文件:行号 + 代码片段
- **可能性**：高 / 中 / 低
- **验证方法**：执行 XX → 观察 YY
- **修复思路**：…

### Step 4：用 AskQuestion 让用户选择根因（或补充假设）

### Step 5：修复 + 即时验证

- 修复前先复述"我将改哪几行、为什么"
- 改完立即跑测试 / 手动复现

### Step 6：补回归测试 + 总结

- 至少 1 个能复现该 Bug 的测试用例
- 1 句话总结：根因 + 修复 + 防复发

## 2. 修复前必须输出

```markdown
## 准备修改
- 文件：path/to/file.ext:行号
- 原代码：…
- 新代码：…
- 修改原因：（对应根因 #N）
- 影响范围：（哪些调用方会受影响）
- 回滚方案：（如何撤销）
```

## 3. 修复完成判定标准

5 项齐全才视为完成：

1. ✅ 根因被明确指认（哪个候选假设被采纳）
2. ✅ 修改的文件清单 + diff 摘要
3. ✅ 回归测试通过（或手动验证通过的证据）
4. ✅ 1 句话总结
5. ✅ 防复发建议

## 4. 验收清单

- [ ] 用户对根因已确认
- [ ] "准备修改"清单已展示
- [ ] 回归测试已写并通过
- [ ] 根因 + 修复 + 防复发 三段总结已写

## 5. 过期条件

- 切换到 TDD 流程（修前必须写失败测试）
- 切换到 AI 自动修复（auto-fix skill）
