## 一、目标与背景

### 1.1 用户原始诉求（按时间线复盘）

| # | 诉求 | 出处 |
|---|---|---|
| 1 | "做一个管理 API key 的库，我可以直接在网站里面直接用" | 初始需求 |
| 2 | "每个功能配置的 key 都不一样，比如 AI 新闻（包含 AI PPT）可以单独配一个 key" | 关键澄清 #1 |
| 3 | "我没有太多成本，默认配 ds-v4-flash 和 GLM-4-7-flash。其他模型我暂时没提供，不代表不能接，你帮我对每个 AI 模型商都遍历一遍" | 关键澄清 #2 |
| 4 | "按功能划分，但一个 key 可以被多个功能使用，默认全部功能都用 ds-v4-flash，可以在各功能设置里配置" | 关键澄清 #3 |
| 5 | "如果功能 Provider 没可用 key，UI 弹窗让用户手动选" | 降级策略 |
| 6 | "把设置页里那个右侧框选的子导航，变成顶部水平导航，而不是左侧那个大导航栏" | 布局澄清 |
| 7 | "顺便给 AI 对话增加开场白、语言风格、角色、输出习惯等人性化设置" | 智能化方向 |
| 8 | "首次进入聊天页给一个轻量引导" | 引导策略 |

### 1.2 解决的核心问题

- **Key 管理零散**：当前 `ApiKey` 表虽存在，但只用于 REST API Token（`provider='aihub-rest'`），**未对接任何 AI Provider**。
- **设置页导航冗余**：当前是 **左侧大导航 + 设置页内还嵌一个左侧 section nav**，二级导航重复。
- **AI 对话无个性化**：当前 `chat.sendMessage` 直接发消息，无 system prompt / 人格 / 风格定制。

### 4.1 数据库改动 — `prisma/schema.prisma`

`model UserPreferences` 新增 6 个字段：

```prisma
/// AI 对话预设风格: rigorous | humorous | friendly | concise | literary
chatPresetStyle     String   @default("friendly")
/// 自定义开场白（AI 每次打招呼怎么说）。null = 不用开场白
chatOpeningLine     String?
/// 角色设定（例：你是 10 年经验的产品经理）
```

### 4.2 预设风格枚举

| 值 | 中文标签 | system prompt 片段 |
|---|---|---|
| `rigorous` | 严谨 | 你是一个严谨的助手，引用必须有据可查，对不确定的内容明确说明 |
| `humorous` | 幽默 | 你是一个幽默的助手，可以用比喻和小幽默，但不要刻意玩梗 |
| `friendly` | 友善 | 你是一个友善、温和的助手，语气自然亲切（**默认**） |
| `concise` | 简洁 | 你追求简洁，能用一句话说清的不用两句，不寒暄不铺垫 |
| `literary` | 文艺 | 你的语言带文学色彩，注重表达的美感，但不过度修饰 |

### 4.5 System Prompt 构建规则

新建 `src/lib/ai/chat-style.ts`：

```ts
buildSystemPrompt(prefs): string {
  const parts: string[] = [];

  // 1. 预设风格（核心人格）
  parts.push(PRESET_STYLE_PROMPTS[prefs.chatPresetStyle ?? 'friendly']);

  // 2. 自定义开场白
  if (prefs.chatOpeningLine) {
    parts.push(`每次对话开始时，先用这句话打招呼：\n"${prefs.chatOpeningLine}"`);
  }

  // 3. 角色设定
  if (prefs.chatPersonaRole) {
    parts.push(`你的角色：${prefs.chatPersonaRole}`);
  }

  // 4. 语言偏好
  parts.push(LANG_PROMPTS[prefs.chatResponseLang ?? 'auto']);

  // 5. 思考深度
  parts.push(REASONING_PROMPTS[prefs.chatReasoningDepth ?? 'normal']);

  // 6. 自定义规则（每行一条）
  if (prefs.chatCustomRules?.trim()) {
    const rules = prefs.chatCustomRules.split('\n').map(s => s.trim()).filter(Boolean);
    if (rules.length > 0) {
      parts.push(`附加规则：\n${rules.map((r, i) => `${i+1}. ${r}`).join('\n')}`);
    }
  }

  return parts.join('\n\n');
}
```

### 5.2 新建 tRPC router — `src/server/routers/ai-keys.ts`

挂在 `_app.ts`：

| Procedure | 入参 | 作用 |
|---|---|---|
| `list` | 无 | 列出本租户所有 `provider != 'aihub-rest'` 的 key |
| `create` | `{ provider, label, apiKey, model? }` | 加密入库，返回明文一次 |
| `revoke` | `{ id }` | 软删除 |
| `test` | `{ provider, apiKey, model? }` | 真发一次 `chat/completions`（max_tokens=1），返回 `{ ok, latencyMs, error? }` |

**示例（test）**：
```ts
test: protectedProcedure
  .input(z.object({
    provider: z.string(),
    apiKey: z.string().min(8),
    model: z.string().optional(),
  }))
  .mutation(async ({ input }) => {
    const adapter = getProviderAdapter(input.provider);
    if (!adapter) throw new TRPCError({ code: 'BAD_REQUEST', message: 'Unknown provider' });
    const start = Date.now();
    try {
      await adapter.testConnection({ apiKey: input.apiKey, model: input.model ?? adapter.defaultModel });
      return { ok: true, latencyMs: Date.now() - start };
    } catch (e) {
      return { ok: false, latencyMs: Date.now() - start, error: (e as Error).message };
    }
  })
```

```ts
export type ProviderProtocol = 'openai' | 'anthropic' | 'gemini';

export interface ProviderAdapter {
  id: string;
  displayName: string;
  protocol: ProviderProtocol;
  baseUrl: string;
  defaultModel: string;
  models: string[];
  docsUrl: string;
  testConnection(opts: { apiKey: string; model: string }): Promise<void>;
  // 后续扩展：buildRequest / parseResponse
}

const ADAPTERS: Record<string, ProviderAdapter> = {
  deepseek: { ... },
  zhipu: { ... },
  // ...
};

export function getProviderAdapter(id: string): ProviderAdapter | null {
  return ADAPTERS[id] ?? null;
}

export function listProviders(): ProviderAdapter[] {
  return Object.values(ADAPTERS);
}
```

## 九、风险与回滚

| 风险 | 缓解 |

## 十三、清理缓存功能（追加任务，最后做）

### 13.1 需求背景

用户希望清理页能：
- 看到**自动清理日志**（cron 跑的内容透明化）
- **手动触发**清理
- **锁定**某些 PPT 早报永不清理
- **不删除**任何内容数据（新闻、对话、收藏、正文）

### 13.2 4 项子决策

| # | 决策 | 选项 |
|---|---|---|
| cache-1 | 范围 | scope-A（仅后端 DB 缓存） |
| cache-7 | 锁定 UI 入口 | lock-ui-B（双入口：「数据与缓存」+ 早报面板） |
| cache-8 | 确认弹窗 | confirm-A（仅 PPT/快照/R2 三项需确认） |
| cache-9 | 自动清理日志 | log-B（localStorage + Upstash Redis） |

### 13.3 UI 设计（设置页第 11 个 tab：「数据与缓存」）

```
① PPT 早报缓存（pptxBase64）         → [立即清理]
② 模型价格快照                       → [立即清理]
③ R2 孤儿文件                        → [立即扫描清理]
④ 自动清理日志（最近 5 次）
```

### 13.4 schema 改动

`DailyReport` 加 `locked Boolean @default(false)`，锁定后永不清理。

### 13.5 关键安全约束

- 所有清理操作必须在事务内执行
- PPT 锁定是**永久的**（用户必须主动解锁）
- 清理失败不影响其他清理项（continue on error）
