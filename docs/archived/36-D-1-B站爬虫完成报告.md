## 四、关键实现说明

### 4.1 不依赖 yt-dlp

原方案（设计文档 06 §3.3）依赖 yt-dlp，但 yt-dlp 是 Python 工具，Vercel serverless 调用子进程有挑战。

**实际方案**：B 站提供了**免认证公开 API**：

| 接口 | 用途 |
|------|------|
| `api.bilibili.com/x/space/arc/search?mid={uid}&order=pubdate` | UP 主视频列表 |
| `api.bilibili.com/x/web-interface/view?bvid={bvid}` | 视频详情（含 desc、cid）|
| `api.bilibili.com/x/player/v2?bvid={bvid}&cid={cid}` | 字幕元数据 |

优势：纯 HTTP + JSON，无子进程，无 yt-dlp 部署复杂度，Vercel 函数兼容。

### 4.2 写入保护机制（迁移自 ai-news-daily）

参考 `docs/06-B站与多模态-增量设计.md §3.5`，逐 UP 主粒度合并：

```
旧 cache  →  Map<uid, BiliUP>
本次抓取  →  List<BiliUP>
合并规则：
  - 本次 news > 0 且 ok → 覆盖
  - 本次失败 → 沿用旧数据，记入 restored 列表
  - 全部失败 → 记入 failed 列表
```

人工测试已观察到真实风控（429 限流），写入保护机制可避免数据被覆盖。

### 4.3 标题切分多风格兼容

橘鸦 / 黑鸦 / infinite 三个 UP 主标题格式不同：

```typescript
parseNewsFromTitle(title):
  - 黑鸦式 "A！B！C！" → 按 "！" 切
  - infinite式 "A，B，C | 8月30日AI日报" → 按 "，" 切
  - 橘鸦式 "X发布 | 8月30日AI早报第503期" → 整体一条
```

### 4.4 跨模态事件融合（D-1 §5.2）

`fuse.ts` 实现：

```
fuseEvent(keyword):
  - NewsItem 关键词匹配（title / summary / relatedModels / companyTags）
  - Model 关键词匹配（externalId / name / provider / description）
  - NewsItem 自动标记 isVideo（通过 media.kind === 'video'）
```

返回 `{ news, models, totalMatches }`，可被新闻详情页调用展示"相关视频 / 相关模型"。

|-----------|------|------|

### 7.1 已知限制

- **B 站风控真实存在**：人工测试触发了 1 次 429/412，写入保护机制可降级
- **字幕正文不索引**：B 站字幕 JSON 的 `body[].content` 是数字索引（指向 content 数组），需要前端下载后再做关键词匹配。后端仅提供时间戳。
- **maxDuration = 300s**：7 个 UP × 5 视频 = 35 个 API 调用，理论可行但吃紧。生产可降到 maxVideosPerUP=3。
