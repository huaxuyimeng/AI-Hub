## 一、5.1 脚本迁移（litellm → chat）

### 改动文件

| 文件 | 改前 | 改后 |
|---|---|---|
| `scripts/expand-synonyms.ts` | `import { litellm } from '../src/lib/ai/client'`<br>`litellm.chat.completions.create({model: 'gpt-4o-mini', ...})` | `import { chat } from '../src/lib/ai/router'`<br>`chat(DEFAULT_MODEL, 'system', messages, { temperature: 0.3, devMock: false })` |
| `scripts/extract-terms.ts` | 同上 | 同上 |

### 关键变化
- **模型**：gpt-4o-mini → deepseek-v4-flash（route-A 默认）
- **调用方式**：`litellm.chat.completions.create({messages, response_format})` → `chat(model, tenantId, messages, options)`
- **响应解析**：`response.choices[0].message.content` → `result.content`
- **dev mock**：保留 `devMock: false`（脚本场景下不应触发 mock，让真实 key 走通）

### 保持的事
- 并发模型能力：dev 无 key 时，**自动用 system 环境变量兜底**（keypool-A）
- 错误处理：保留 try/catch + 单项失败 continue
- 输出格式：保持 `[label] [count] 个同义词` 的中文格式

## 三、5.3 cache 日志升级 Upstash Redis

### 改动文件
- `src/server/routers/cache.ts`：内存数组 → Upstash Redis（fail-open 内存降级）+ 自动清理入口

### 接口升级
| 字段 | 原（内存） | 新（Redis） |
|---|---|---|
| 存储位置 | 进程内数组 | Redis list `cache:cleanup-log` |
| 生命周期 | 进程重启丢失 | 30 天 TTL，最多 50 条（`LPUSH` + `LTRIM` + `EXPIRE`） |
| 多实例 | × | ✅ 多 Next.js 实例共享 |
| 读 API | `getCleanupLog()` | 不变（向后兼容，前端无感） |

### 新增自动清理入口 `runAutoCleanup()`
```typescript
export async function runAutoCleanup(opts: {
  cleanPpt?: boolean;
  cleanSnap?: boolean;
  scanR2?: boolean;
  source?: string;
} = {}): Promise<{ ppt: number; snap: number; r2: number; logs: CleanupLogEntry[] }>
```

供 cron 调用（无登录态），日志 source 标 `cron:auto`。

### Redis 未配置 / 异常时降级
- `redisClient()` 返回 null → pushLog 自动走 `memLogs` 数组
- Redis 抛错 → catch 后降级，绝不让日志失败拖垮清理
- 前端 `getCleanupLog` 读不到 Redis 时返回内存数组（多实例间不一致，但至少 visible）
