## 二、本轮修复明细（10 项）

### CRITICAL 1: resolveApiKey 致命 bug

**问题**：DB 只存 `keyHash`，无法还原明文。`resolveApiKey` 拿到 dbKey 后没有 return，导致**用户存的 API key 永远不会被用于真实 API 调用**——永远 fall through 到 env。

**修复**：
- `prisma/schema.prisma`：ApiKey 加 `encryptedKey String?` 字段（可解密）
- `src/lib/crypto.ts`（新建）：AES-256-GCM 工具，密钥来自 `APP_SECRET` 环境变量
- `src/lib/ai/key-resolver.ts`：解密 `encryptedKey`，解密失败时优雅降级到 env
- `src/server/routers/ai-keys.ts`：create 时调用 `encrypt(plainKey)` 存密文

**验证**：修改后用户存的 key 真的会被 router 使用。

### CRITICAL 2: Settings 布局不符合 P0 决策

**问题**：P0 §3.1 明确要求"设置页内子导航 → 顶部水平 tab + 下划线高亮"。但 `settings/page.tsx` 还是左 `<aside>` nav。

**修复**：
- 桌面端：改为顶部水平 tab（VSCode / GitHub 风格），底部边框 + 下划线高亮当前 section
- 移动端：保留 `<select>` fallback
- 11 个 section 全都在水平 tab 内，wrap 处理溢出

### HIGH 3: sanitizeError 覆盖不足

**问题**：原版只覆盖 `sk-` / `sk-ant-` / `AIza` 和 generic 40+ base64。后者会**误杀**合法 URL/JSON 字符串。

**修复**（`src/server/routers/ai-keys.ts`）：
- 新增 6 个 provider 的精确前缀正则：`sk-ant-*` `sk-*` `AIza*` `xai-*` `AKLT*`（Zhipu 部分已知）
- 新增 `Bearer xxx`、`glpat-*`（GitLab token）等敏感词
- generic base64 改为**上下文敏感 redact**：只在 `api_key/key/token/authorization` 关键词附近时才 redact 长 base64
- 长数字 `≥20` 位：保留（避免误杀）

### MEDIUM 4: ApiKey 缺唯一约束

**问题**：`schema.prisma` 缺 `@@unique([tenantId, provider, label])`，靠 ai-keys.ts 应用层校验。

**修复**：在 `prisma/schema.prisma` 的 `model ApiKey` 加 `@@unique([tenantId, provider, label])`。`pnpm prisma generate` 后客户端类型同步更新。

### LOW 5: ChatStylePanel maxLength 不统一

**问题**：UI cap 在 1000，schema 允许 2000，doc 说 2000。

**修复**：UI 提到 2000，counter 也同步。

### LOW 6: slide-engine export 冲突

**问题**：`checkQA/getErrorCount/getWarnCount` 在 lint.ts 和 gate.ts 都定义，`qa/index.ts` re-export 时冲突。

**修复**：
- lint.ts：删除我的临时副本（gate.ts 里已有原版）
- `src/app/api/slide-engine/preview/route.ts`：从 `'./lint'` 改 import `'./gate'`
- preview route 的 `Buffer` 类型错误：改用 `new Uint8Array(buffer)`

### 验证 7: _debug-render.ts 路径

**问题**：subagent 没验证实际路径是否正确。

**修复**：读取确认 ✅ 路径正确（`../src/lib/slide-engine/...`）

### 误判 8: ChatStylePanel hasChanges 漏 reasoningDepth
