### 0.2 市调：AI PPT 通病清单（2026）

调研了 Gamma / Canva / Beautiful.ai / Pitch / PowerPoint Copilot / Plus AI / Slidespeak 等 16 个主流工具，核心用户投诉集中在 10 类：

| # | 痛点 | 发生率 | 典型案例 |
|---|---|---|---|
| 1 | **导出失真**：预览完美，导出 PPTX 后字体/颜色/间距全乱 | 极高 | Gamma / Beautiful.ai 用户高频投诉 |
| 2 | **模板同质化**：所有 AI PPT 看起来像同一个妈生的 | 高 | 主流工具收敛到相似模板 |
| 3 | **AI 幻觉**：AI 生成虚假数据、假统计数据、假引用 | 中高 | 多个工具均被用户发现在 PPT 里引用不存在的研究 |
| 4 | **内容泛化**：生成的内容对所有人通用，对具体受众毫无针对性 | 中高 | 医疗/制造/零售受众收到完全相同的语言 |
| 5 | **品牌失控**：Logo 错位、色值偏差、字体被替换 | 中 | 几乎所有工具均无法完美对齐品牌规范 |
| 6 | **隐私风险**：上传文档被第三方服务器处理，企业数据外泄 | 中 | 财报/商业计划被用户质疑上传安全 |
| 7 | **隐性成本**：实际成本是订阅费的 2.3 倍（含培训/修复/迁移） | 中 | BCG 2025 调研数据 |
| 8 | **策略性思维退化**：团队把 AI 当答案，不做内容判断 | 中低 | 过度依赖 AI 生成，丧失内容主导权 |
| 9 | **无溯源机制**：内容来自哪里、置信度如何，全黑盒 | 中低 | 无任何工具内置信源透明机制 |
| 10 | **时效性差**：基于通用知识生成，无法反映当日最新动态 | 中低 | 大多数工具生成的是"通用 PPT"而非"今日新闻 PPT" |

### 0.3 我们的差异化定位

针对上述痛点，AIHub AI 早报 PPT 的核心差异：

| 痛点 | AIHub 解法 |
|---|---|
| 导出失真 | **pptxgenjs 直接生成 .pptx**，无中间格式转换，所见即所得 |
| 模板同质化 | **6 套独立主题**（纸面/墨韵/薄荷/薰衣草/暖橙/海洋）+ **AI 原创排版**，非模板填充 |
| AI 幻觉 | **信源透明**：每条新闻标注来源+发布时间；数据来自多源 RSS/API，无 AI 编造 |
| 内容泛化 | **选题由真实新闻驱动**，每条内容对应真实事件，含一手链接 |
| 品牌失控 | **固定色板体系**，accent/bg/fg/muted/line 全部硬编码，无随机 |
| 隐私风险 | **服务端生成**，用户不上传任何文档；LLM 仅用于改稿，不处理企业数据 |
| 无溯源 | **置信度 A/B/C/D 标注** + **独立信源数量** + **一手来源链接**，全链路透明 |
| 时效性 | **每日 7:00 cron 触发**，当日最新数据，窗口精确到北京时间 |

## 1. 页面结构（完整规格）

### 1.1 页面地图

每份 PPT 共 **5 + N 页**（N = 当日入选新闻数，4~6 条）：

```
P1  封面
P2  今日要点（3~4 条核心事件速览）
P3  信源透明度（置信度评级说明 + 信源构成饼图）
P4  入选新闻①（标题 + 摘要 + 点评 + 来源）
P5  入选新闻②
...
P(N+2)  入选新闻(N)
P(N+3)  数据趋势（当日统计 + 近7天柱图 + 分类分布）
P(N+4)  尾页（透明声明 + 产品署名）
```

**基准（2026-08-29 真实数据）：** 216 条候选 → LLM 选题 4~6 条 → **共 9~11 页**。

### 1.2 页面内容详解

#### P1 · 封面

**布局**：左上角 Logo + 右上角 AIHub 标识；中央大标题 + 日期；底部一行副标题（当日 AI 动态一句话导读）。

**数据示例（2026-08-29 真实数据）：**
```
主标题：AI 新闻日报
副标题（LLM 生成）：大模型算力竞争升级、具身智能加速落地、国产开源生态持续扩张
日期：2026.08.29
底部署名：多源聚合 · 交叉验证 · 每日自动生成
```

**设计要点**：
- 背景：主题色 bg（6 套主题任选）
- 标题字号：48pt，bold，主色 fg
- 日期：20pt，次色 muted
- 副标题：15pt，fg，居中，最大宽度约束在 65% 页面宽度

---

#### P2 · 今日要点

**布局**：左侧蓝色竖条 + "今日要点" 标题 + 开场白；右侧 N 个编号卡片，每个卡片含序号圆点 + 要点标题 + 一句话说明。

**数据示例（2026-08-29 真实数据，LLM 选题 4 条）：**
```
开场白（≤60字）：Anthropic 胜诉五角大楼、腾讯混元 Hy4 开源、Claude Code 上下文污染争议成焦点。

① Anthropic 诉五角大楼案胜诉
   大模型与监管的边界首次由法院裁定

② 腾讯混元 Hy4 开源：770B 参数杀入第一梯队
   Coding 能力实测超越 GPT-4o mini

③ Claude Code 上下文污染：Agent 正在制造"代码屎山"
   额度回落，团队开始反思 Agent 工程的边界

④ EPA 批准数据中心豁免污染审查
   AI 扩张与环保的冲突正式进入政策博弈
```

**设计要点**：
- 每条要点最大宽度：`W - MARGIN*2 = 13.33 - 1.4 = 11.93 in`
- 序号圆点：accent 色，直径 0.42in，bold 白字
- 要点标题：15pt bold，fg，超长自动缩字号（`fit: 'shrink'`）
- 一句话说明：11.5pt，次色 muted

---

#### P4~P(N+2) · 入选新闻详情页

每条入选新闻独占一页。**这是 PPT 的核心内容页。**

**布局**：

## 2. 视觉设计系统

### 2.1 6 套主题色板

每套色板均包含 bg（背景）/ fg（主文字）/ muted（次文字）/ accent（强调）/ softBlock（信息框）/ line（分割线）6 个 token，**预览（HTML）与 .pptx 共用同一套 HEX 值**。

| 主题 ID | 名称 | bg | fg | muted | accent | softBlock | line | 适用场景 |
|---|---|---|---|---|---|---|---|---|
| `paper` | 纸面奶白 | `FBFAF6` | `2E2C28` | `8A857A` | `C98F2D` | `F3EFE4` | `E6E0D2` | 企业晨会 / 正式场合 |
| `ink` | 墨韵深褐 | `1F1C19` | `F2EEE8` | `A89F94` | `D9A441` | `2C2823` | `3A352E` | 科技媒体 / 晚间分享 |
| `mint` | 薄荷清风 | `F6FBF8` | `22302A` | `7E9189` | `2F9E6E` | `E9F4EE` | `DCEAE2` | 健康 / 可持续 / 清新风格 |
| `lavender` | 薰衣草紫 | `F9F7FC` | `2B2733` | `8D8798` | `7C6BC8` | `EFEAF8` | `E3DDF0` | 创意 / 教育 / 女性受众 |
| `amber` | 暖橙早报 | `FDF8F1` | `33291C` | `99886F` | `E07B26` | `F8EDE0` | `EFE3D2` | **默认主题** / 温暖亲切 |
| `ocean` | 海洋蓝 | `F5F9FC` | `1F2A33` | `7C8B96` | `2779BD` | `E8F1F8` | `DBE7F0` | 科技 / 商务 / 专业严谨 |

**色值来源说明**：对齐应用 OKLCH 预设的 HEX 转换版（pptx 不支持 OKLCH）。

### 2.3 间距规范

| 参数 | 值 | 说明 |
|---|---|---|
| 页面尺寸 | 13.33 × 7.5 in（16:9） | pptxgenjs 原生 16:9 布局 |
| 页边距（MARGIN） | 0.7 in（两侧） | 统一左右边距 |
| 顶栏高度 | 0.7 in | Logo + 来源 chip + 时间 |
| 页脚高度 | 0.35 in | 页码 + 水印 |
| 分割线粗细 | 0.012 in（约 1px） | 水平分割线 |
| 信息框圆角 | 0.08 in | 点评框 / 趋势总结框 |
| 来源 chip 圆角 | 0.06 in | 顶部来源标签 |

### 2.4 CJK 宽度处理

中文字符视觉宽度 ≈ 1.0 单位，英文/数字 ≈ 0.5 单位。chip 宽度使用 `estimateVisualWidth()` 计算：

```ts
function estimateVisualWidth(s: string): number {
  let w = 0;
  for (const ch of s) {
    if (/[\u3000-\u9fff\uff00-\uffef\uac00-\ud7af]/.test(ch)) {
      w += 1;
    } else {
      w += 0.5;
    }
  }
  return w;
}
// chip 宽度（英寸）= estimateVisualWidth(sourceName) * 0.19 + 0.4
```

## 3. 独特亮点设计（让人记住 AIHub 的记忆锚点）

### 亮点 1：信源透明度页（无任何竞品提供）

**痛点对应**：市面所有 AI PPT 均无信源透明机制，内容可信度全靠用户自行判断。

**设计实现**：在 P3 独立页面展示：
- 置信度 A/B/C/D 的含义说明（独立信源数判定，非人工核实）
- 各信源当日贡献条数（10 个信源柱图）
- 透明声明：评级仅依据信源数量，未经人工核实

**用户记忆锚点**：以后看到"AI PPT 有信源页"，就想到 AIHub。

---

### 亮点 2：置信度标签（可触达、差异化强）

**痛点对应**：所有 AI PPT 内容均匀分布，没有优先级感知。

**设计实现**：每条入选新闻详情页（P4~）右上角有一个醒目的置信度 chip：
- `A 确证`（深绿，≥3 个独立信源）→ 最高优先级
- `B 高`（橙色，=2 个独立信源）
- `C 中`（蓝灰，=1 个信源）
- `D 存疑`（红色，多源矛盾或信息存疑）

**数据示例（2026-08-29）**：
- "Anthropic 诉五角大楼" → A 确证（hn + techcrunch + the verge = 3 个独立英文源）
- "英伟达收购 Hugging Face" → B 高（infoq + techcrunch + 极客公园 = 3 个）
- "Claude Code 上下文污染" → C 中（leiphone 单源，但含 relatedSources）

**用户记忆锚点**：看完 PPT，脑子里有"哪条新闻最可信、哪条需要进一步核实"的清晰判断。

---

### 亮点 3：每日 AI 动态一句话（封面副标题，LLM 生成）

**设计实现**：封面底部副标题行（≤30 字），由 LLM 从入选新闻中提炼一句概括。

**数据示例（2026-08-29）**：
```
大模型算力竞争升级、具身智能加速落地、国产开源生态持续扩张
```

**对比竞品**：Gamma/Canva 等工具的封面副标题是通用描述语（如"Transform your ideas"），AIHub 的是**当日真实动态**，不可预测但高度相关。

**用户记忆锚点**：每天打开 PPT，第一眼看到的是"今天 AI 圈发生了什么"，而非泛泛的模板文字。

---

### 亮点 4：数据趋势页（让新闻可量化）

**设计实现**：P(N+3) 右侧展示：
- AI 厂家提及 Top5（Anthropic / OpenAI / 腾讯 / 英伟达 / 谷歌）
- 近 7 天新闻量柱图（7 根柱，直观感知新闻量周期）
- 分类占比（其他 / AI Coding / 具身智能）

**数据示例（2026-08-29）**：本周具身智能从 8 条/天 升至 14 条/天，占比从 14% 升至 43%。

**用户记忆锚点**：看到"具身智能连续 3 天上升"，立刻感知到行业热点迁移。

---

### 亮点 5：点评区（让读者知道"为什么这条重要"）

**设计实现**：每条新闻详情页底部有一个 softBlock 色块，写 LLM 改写的一句话点评（≤30 字）。

**对比竞品**：Gamma/Canva 等工具只展示标题+摘要，读者自行判断重要性。AIHub 的点评是 AI 替读者做了第一次判断。

**数据示例（2026-08-29）**：
- Anthropic 诉五角大楼 → "大模型与监管的边界首次由法院裁定"
- 腾讯混元 Hy4 开源 → "Coding 能力实测超越 GPT-4o mini，国产模型第一梯队确认"
- Claude Code 上下文污染 → "Agent 正在制造'代码屎山'，团队开始反思工程边界"

**用户记忆锚点**：看完 PPT，对每条新闻的印象不只是标题，而是一个判断。

---

### 亮点 6：一手来源链接（防幻觉、防侵权）

**设计实现**：每条入选新闻详情页，在点评框下方（如果空间允许）或在摘要区底部，展示该新闻的**一手来源 URL**（截断至 58 字符，可点击）。直接粘贴网址，而不是"<div>网址<\div>"，没有标签语言之类的。



**用户记忆锚点**：每条内容都有来源可查，AIHub 不替用户捏造内容。

## 4. 字数/内容约束

所有文字均受服务端硬约束（P0 保障），避免 PowerPoint 排版溢出：

| 新闻摘要 | 90 字 | 自动截断 |
| 点评 | 30 字 | 一句话说明 |
| 趋势总结 | 120 字 | trendText 字段 |

## 5. 技术实现要点（与 UI 共用同一套逻辑）

### 5.1 所见即所得

**预览（`SlidePreview.tsx`）** 和 **.pptx（`build-pptx.ts`）** 必须共用：
- 同一套 `BriefingPalette` 色板（`themes.ts`）
- 同一套 `estimateVisualWidth()` 宽度算法
- 同一套字数的 `LIMITS` 约束（`types.ts`）

### 5.2 降级路径（永不输出半成品）

```
AI 改稿失败（LLM 超时/拒答）
    ↓
buildFallbackContent() → degraded=true
    ↓
前端面板显示"降级版"标注
    ↓
下载 → Markdown 日报（.md，非 .pptx）
    ↓
绝不在 PPT 里出现半成品内容
```

### 5.3 幂等性

- 同一天只有一份早报（`upsert` 操作）（可以在界面内重新生成）（早报的新闻数据时间段为当天的8:00am到昨天的8:00am，时间段可以在设置功能里面自由设置整时段，如果时间在下午，则是晚报）
- 重新生成时 `deleteMany + 重新 generate`
- 缓存键：(date, theme)，换主题自动清 pptxBase64
