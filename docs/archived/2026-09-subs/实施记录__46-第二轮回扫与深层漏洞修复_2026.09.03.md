## 一、本轮发现并修复的问题

### 🔴 CRITICAL 1: `toPublicProject` 函数不存在 → project.ts 整体无法编译

**症状**：subagent 漏掉的**最严重**的 bug。
- `src/server/routers/project.ts:12` import 了 `toPublicProject` from `'../../lib/sanitize'`
- 但 `toPublicProject` 在整个代码库**完全没定义**
- 导致 **project 路由整个挂掉**（projects/[id]/page.tsx、projects/page.tsx、projects/new/page.tsx、workbench/page.tsx 全部 tsc 失败）

**修复**：在 `src/lib/sanitize.ts` 实现 `toPublicProject()`，返回带默认值的 `PublicProject`（不返回 null，避免触发 `'p' is possibly null`）。

### 🔴 CRITICAL 2: chat.ts 的 mock 分支泄漏原始错误信息

**症状**：chat.ts dev-mock 分支用了 `(e as Error).message` 直接拼接到客户端可见的 `aiText`。OpenAI/Anthropic 的错误信息可能含：
- provider URL（`https://api.openai.com/v1/chat/completions`）
- 部分 API key 字符
- 模型版本等内部细节

**修复**：
- 抽 `sanitizeError()` 到 `src/lib/sanitize.ts`（统一所有 router 使用）
- chat.ts 的 mock 分支调用 `sanitizeError((e as Error).message)`
- ai-keys.ts 删除本地 `sanitizeError`，改 import 共享版

### 🟡 MEDIUM 3: `.env.example` 缺 APP_SECRET

**症状**：AES-256-GCM 加密需要 `APP_SECRET`，但 `.env.example` 没说明。

**修复**：在 `.env.example` 加 `APP_SECRET` 段（含生成命令 `openssl rand -base64 32`），强调"**生产环境必须设置**"。

### 🟢 LOW 4: PublicProject 缺字段

**症状**：subagent 上一轮没注意到 `PublicProject` 缺 `slug` / `visibility` / `latestScore` 字段，前端用了这些字段。

**修复**：补齐 `PublicProject` 类型所有字段。

### 🟢 LOW 5: projects/page.tsx p.slug 没用 optional chaining

**症状**：`slug` 在 schema 里 nullable，TS 严格模式要求显式 null check。

**修复**：改为 `p.slug?.toLowerCase().includes(k) ?? false`。
